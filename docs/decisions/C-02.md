# C-02 — Identité persistante et sessions

2026-11-05 ; choix effectués sous délégation explicite du responsable produit, confirmée par la demande de poursuivre en autonomie. F-001/F-002, US-001/US-009, NFR-02/04/05/13 ; ROADMAP P1.1/P1.2/P1.9. ADR-0008 accepté pour ce contrat. API REST locale versionnée retenue, aucune règle financière modifiée.

## Contrat implémenté

- PostgreSQL 18.6, pilote pgx via database/sql ; données persistantes, requêtes paramétrées. Schéma initial embarqué, transaction et verrou consultatif pour les démarrages concurrents ; version 1 enregistrée. La prochaine évolution devra être une migration distincte, pas une réécriture du schéma initial.
- Adresse mail normalisée en minuscules ; mot de passe de 12 à 72 octets, bcrypt coût 12, sel généré par la bibliothèque. Pas de mot de passe dans les réponses ou logs.
- Inscription désactivée par défaut, activation explicite par l’exploitant. Aucun premier inscrit administrateur. Réponse 202 identique pour adresse existante ; aucun envoi de mail ni validation de propriété d’adresse promis.
- Session opaque aléatoire 256 bits, empreinte SHA-256 uniquement en base. Durée absolue 12 h. Chaque connexion révoque les anciennes sessions de cet utilisateur ; déconnexion révoque la session courante ; expiration vérifiée côté serveur. Purge des sessions expirées lors d’une connexion.
- Cookie HttpOnly, SameSite=Strict, Path=/, Secure en HTTPS. Origine exacte obligatoire sur toutes les écritures, JSON strict et corps limité à 4 Kio ; pas de CORS. Plafond global de 20 tentatives par minute sur inscription/connexion, mémoire bornée, remis à zéro au redémarrage. Compromis volontaire pour instance personnelle ; limite persistante/distribuée non livrée.
- GET /api/v1/me déduit le propriétaire uniquement de la session ; aucun paramètre d’identifiant ne permet de changer l’utilisateur. Aucune route de consultation d’autrui ou d’administration.
- HTTPS exigé par défaut. HTTP de laboratoire possible uniquement via ATLAS_INSECURE_HTTP=true et origine http explicite ; ne pas y utiliser de vrais identifiants sur un réseau non fiable. Le proxy TLS n’est pas livré dans ce lot.

## Exploitation et limites

`docker-compose.auth.yml` complète le Compose existant sans casser le démarrage du socle : PostgreSQL sans port hôte, volume persistant, rôle atlas non superuser propriétaire de sa base ; migrations au démarrage. Le secret reste dans l’environnement Docker de l’exploitant, jamais dans Git. Mot de passe PostgreSQL URL-safe nécessaire pour le DSN (hex aléatoire recommandé). Le script d’initialisation ne s’applique qu’à un volume neuf.

Pas de récupération de compte, changement de mot de passe, rôle administrateur ni écran de connexion livrés. Ne pas déclarer C-02 complet sur tous les parcours utilisateur : ce lot livre le backend et son contrat. Pas de validation T-09 sur des portefeuilles encore inexistants ; les tests portent sur les identités effectivement disponibles.

Reprise : arrêter l’API, conserver le volume ; aucune migration destructive. Le schéma est additif. Une restauration d’instance n’est pas encore prouvée et reste un jalon distinct ; ne pas exécuter `down -v` sur des données à conserver.

Sources techniques consultées : [pgx](https://pkg.go.dev/github.com/jackc/pgx/v5/stdlib), [bcrypt](https://golang.org/x/crypto/bcrypt), [versions PostgreSQL](https://www.postgresql.org/docs/release/). Versions des modules exactes dans go.mod/go.sum.

## Preuves de validation

- Dans Go 1.27.3 conteneurisé : `gofmt -w .`, `go mod tidy`, `go vet ./...`, `go test -race -v ./...`, `go build ./...` réussis. Test PostgreSQL exécuté avec ATLAS_TEST_DATABASE_URL vers le service PostgreSQL 18.6 de test et le rôle atlas non superuser.
- Scénarios réussis : deux utilisateurs isolés sur /me malgré un paramètre user_id étranger, cookie falsifié/absent, mauvais mot de passe, origine étrangère/absente, inscription désactivée, rotation, révocation, expiration, rate limit, JSON invalide/inconnu/trop volumineux, migration rejouée.
- Compose principal et complémentaire : configuration valide ; image reconstruite ; API et base healthy. Inspection SQL : rôle atlas non superuser, sans CREATEDB/CREATEROLE.
- HTTP réel sur port de test 18082 : inscription → connexion → /me → redémarrage API → /me avec même session → déconnexion, réussi avec compte synthétique.
- `git diff --check` réussi. Services de test arrêtés ; volumes et comptes synthétiques conservés, aucune suppression. Aucun service utilisateur existant modifié.
- Pas de test UI (aucun écran), scan de vulnérabilités Go, restauration de sauvegarde, charge ou CI distante exécutés. Les tests d’isolation financière attendent les futures ressources métier. Alertes npm du socle inchangées.
