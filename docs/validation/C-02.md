## Rejouer les suites du dépôt

Depuis `web/`, avec `npm ci` et Chromium installé (`npx playwright install chromium`) :

```sh
npm run lint
npm run build
npm test
# Vite doit être actif sur 127.0.0.1:5173 :
npm run test:browser
npm run test:a11y
# API/base dédiées, inscription activée et origine correspondante :
ATLAS_E2E_ORIGIN=http://127.0.0.1:5173 ATLAS_E2E_TEST_INSTANCE=true npm run test:e2e
```

`ATLAS_CHROMIUM` sélectionne un Chromium système. `ATLAS_A11Y_ORIGIN` peut sélectionner un hébergement du build statique. La suite E2E accepte aussi une origine HTTPS exacte et conserve les comptes synthétiques. Pour une CA privée, configurer une confiance réelle et isolée dans le navigateur et le client Node ; ne pas utiliser `ignoreHTTPSErrors` ou désactiver TLS.

Depuis `backend/`, fournir `ATLAS_TEST_DATABASE_URL` pour une base dédiée avant `go test -race -v ./...`. Sans cette variable, le test d’intégration PostgreSQL est ignoré et ne constitue pas une preuve DB.

## Réserves et portée

1. Le Dockerfile multi-stage original n’a pas été reconstruit entièrement : le stockage vfs de l’environnement a saturé lors du téléchargement de l’image Go complète. Validation remplacée explicitement par compilation Go exacte et image scratch de runtime. Build Docker complet et exécution ARM64 restent à faire dans un environnement adapté.
2. HTTPS local prouvé avec une CA isolée ; aucun domaine public, renouvellement de certificat, proxy de production livré ou déploiement distant validé.
3. Axe, inspection mobile et contrôles clavier ne remplacent pas une recette complète avec lecteurs d’écran et utilisateurs. Les autres moteurs de navigateur n’ont pas été testés.
4. La restauration prouve le scénario de l’identité actuelle sur données synthétiques. Aucune sauvegarde quotidienne automatisée, politique de conservation ni procédure de production complète n’est déclarée livrée. Les clés de l’expérience restent séparées de l’archive dans `work/` ; leur gestion de production reste à définir.
5. La récupération de compte, les portefeuilles, le ledger et les données financières restent absents. Aucun scénario financier T-* déclaré passant sur des fonctionnalités non implémentées.
6. Les données et volumes de test sont conservés ; services de validation arrêtés en fin de recette. Aucun commit, push, PR ou déploiement réalisé.
